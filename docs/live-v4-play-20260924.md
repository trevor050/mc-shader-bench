# Live V4 play and memory snapshot, 2026-09-24

The ShaderBench instance was relaunched into BenchWorld after the user restarted
the long-running app session. Windows available physical memory rose from about
5.75 GiB before the restart (Minecraft closed) to 10.89 GiB afterward
(Minecraft closed). This change does not identify a leak: the old Codex process
had about 2.2 GiB resident plus several `windows-mcp` workers, and multiple
processes and cached pages changed when the app session ended.

With Minecraft relaunched, shaders initially off, the game returned to the
Nether with DH at its saved 512-chunk radius. A settled BenchCam status was
responsive and available physical memory was about 7 GiB. The earlier launch
while only 5.75 GiB was available had instead stopped at Prism's low-memory
dialog against the instance's 8 GiB max heap; the user then continued the
launch. No heap or DH config value was changed here.

The user enabled `ClaudeBenchV4Art` and moved around in the Nether. BenchCam
reported the exact Art guard active and DH 64/512 active/saved, with about 881
DH GL buffer IDs versus about 3,500 at shaders-off 512. The opt-in detailed DH
ledger was not enabled, so buffer-ID count is not a byte measurement.

Passive PresentMon v2 captured 1,538 frames over 15 seconds at the live user
view, without changing camera or game state:

| Measure | Median | p95 | p99 | Maximum |
| --- | ---: | ---: | ---: | ---: |
| Displayed time | 9.826 ms | 14.401 ms | 16.962 ms | 32.242 ms |
| Frame time | 9.780 ms | 14.305 ms | 16.971 ms | 32.373 ms |
| CPU Busy | 9.682 ms | 14.143 ms | 16.582 ms | 32.228 ms |
| GPU Busy | 7.566 ms | 13.331 ms | 16.142 ms | 17.642 ms |

The displayed-time median corresponds to about **102 FPS** in this short
moving Nether sample. This is an actual display-tracked sample, unlike earlier
monitor-off GL query and app-only captures. It is one scene, one pack, one
15-second interval, without an old-stack A/B/A control. It does not establish
an FPS improvement or eliminate the intermittent long-stall risk. No
multi-second stall appeared in this interval.

The 14 telemetry samples showed available physical memory 6.36 to 6.47 GiB
and Minecraft process dedicated GPU allocation 4.18 to 4.24 GiB. These values
were steady across the short capture, not a leak trend. At one live snapshot,
Minecraft had 4.64 GiB physical working set and 12.52 GiB private bytes, while
JVM heap used was about 1.20 GiB and committed about 3.92 GiB. Process private
bytes are not equivalent to physical RAM or DH heap.

Afterward the user switched shader packs. A brief `Responding=false` during a
reload recovered; `latest.log` showed render-worker restart and the server
saving/pausing, not a fatal crash. Under Bliss, the exact Art guard cleared,
DH returned to active 512, and global GPU VRAM reached about 9 GiB. This is a
different workload, not evidence of a leak.

The shader-menu cleanup archived 38 old `ClaudeBench*` experiment entries to
`minecraft/shaderpacks-archive-20260924` with a manifest. Their source targets
remain intact; the current `ClaudeBenchV4Art` junction is the sole active
project pack in `shaderpacks`. The third-party reference packs remain. The
guarded Art trial watchdog armed for the exact Java PID and was canceled after
the capture; it did not stop the game or change shader state.

Raw evidence: `harness/out/live-art-play-20260924/art-present.csv`, its
telemetry CSV and capture JSON, and `harness/out/live-v4-guard-20260924/`.
