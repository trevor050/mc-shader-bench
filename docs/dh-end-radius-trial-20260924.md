# Opt-in End DH radius trial, 2026-09-24

The Art End DH fragment path discards/fades fully by 430 blocks in `end_lod.glsl`, and the End composite reaches full haze by 450 blocks. A 64-chunk Distant Horizons radius is 1,024 blocks, leaving a conservative distance margin beyond those shader cutoffs. This motivated an initial 64-chunk test. A preliminary capture appeared to lose a distant End island horizon at that radius, but shaders were off during the capture, so it is not valid evidence of the Art-on result. The adapter allows guarded comparisons at 128, 256, and 512 chunks. The shader evidence does not establish that any radius is visually equivalent or faster.

The BenchCam adapter adds `dhend on|off|status|radius <chunks>`. The End trial is off by default and requests 64 LOD chunks unless changed at runtime; valid values are in `[64, DH saved radius]`. It changes only DH's in-memory public API override. Its saved TOML value remains the baseline. Repeating the currently selected and active target is a no-op. The End override is gated on pinned Iris 1.11.4 reporting an active shader pipeline and exact loaded pack name `ClaudeBenchV4Art`. Iris reload is synchronous; on shader disable or a different pack, the frame-head hook clears the override before DH draws the next frame. The existing Nether trial remains independently controlled by `dhtrial on|off|status|radius <chunks>` and keeps its startup property and radius behavior.

When the trials are both enabled, BenchCam applies only the target for the active client dimension. On Nether/End/Overworld transitions it clears its recorded API value before applying the next dimension's enabled target. `dhstatus` reports the active (`getValue`), saved (`getTrueValue`), and API (`getApiValue`) values, along with both independent enable states, the owner dimension, and `apiOwner=not_exposed`. DH provides no API ownership token: `owned` is local bookkeeping, and if another mod replaces the radius override with the same numeric value, BenchCam cannot tell and may clear that value. The cleanup check protects only against a different numeric value. Run both trials only on the pinned stack with no other DH API radius writer. Clear failures block another application and continue through the existing bounded retry/backoff path.

## Guarded runtime results

The first 512 → 64 → 512 run accidentally kept Iris shaders **off**. The log explicitly reported `enableShaders=false`, and its captures show the vanilla black End sky. At the central island, [A1](../harness/out/dh-end-radius-trial-20260924/a1-512.png) and [A2](../harness/out/dh-end-radius-trial-20260924/a2-512.png) show a continuous band of distant DH islands, while [B](../harness/out/dh-end-radius-trial-20260924/b-64.png) loses that band. This is a real shader-off regression if the radius override remains enabled across a shader toggle. It says nothing about Art's fragment fade; the original conclusion in commit `b33cb13` that Art's fade thresholds failed was wrong.

A second guarded run explicitly enabled Iris. `latest.log` reported `Using shaderpack: ClaudeBenchV4Art` before the captures, and the images have Art's purple End sky and haze. On MC 26.2 / Iris 1.11.4 / DH 3.3.2 at vanilla render distance 32, the fixed 1920×1080 central-island pose was `(0.5,105,0.5)`, yaw 0, pitch 15. Each phase settled for 400 ticks, then recorded a full-resolution screenshot, 300 render-thread samples, and 10 process/GPU-memory samples. The monitors remained off. `dhstatus` reported `active/api/true` as `512/null/512`, `64/64/512`, then `512/null/512`; all telemetry samples had empty errors.

| Art-on phase | Render-thread median / p95 | Dedicated GPU allocation | Java private bytes |
| --- | ---: | ---: | ---: |
| 512 A1 | 4.569 / 6.478 ms | 2.025 GiB | 8.462 GiB |
| 64 B | 2.051 / 2.889 ms | 0.666 GiB | 5.718 GiB |

Process allocation and render-thread time both fell at 64 and returned near their initial levels at 512. These are **not** whole-frame GPU Busy, presentation intervals, or on-screen FPS. The [Art-on A1](../harness/out/dh-end-art-on-trial-20260924/a1-512.png), [B](../harness/out/dh-end-art-on-trial-20260924/b-64.png), and [A2](../harness/out/dh-end-art-on-trial-20260924/a2-512.png) central-island images retain the same foreground and hazy sky without the shader-off horizon loss. An outer-island A/B was also captured at `(1100,130,0)` after only 180 ticks per phase; ongoing LOD loading changed the far-left silhouette, so that pair is inconclusive and is not used as a visual pass.

## Art-active guard check

After the two image runs, the adapter gained an exact Art-active guard. An independent source review and offline build passed. A third short guarded live check then exercised the new jar in the End: with `dhend on` and shaders off, status remained `endPackActive=false active=512 api=null true=512`; after Art loaded and settled, it reported `endPackActive=true active=64 api=64 true=512`. Turning shaders off restored `512/null`, turning Art back on restored `64/64`, switching to the successfully loaded `ClaudeBenchBaseline` pack restored `512/null`, and switching back to Art restored `64/64`. End → Overworld → End with Art on cleared and reapplied the override by dimension. Each state was checked after 80 ticks for shader/pack changes or 40 ticks for dimension changes. The Iris log confirms both named packs loaded and each BenchCam apply/clear. This validates settled state transitions; exact per-frame clear timing was established by the reviewed `renderFrame` HEAD path, not measured with a frame-by-frame runtime trace. The verified-PID watchdog armed and canceled normally with empty stderr.

## Settled outer-island views

A fourth guarded Art-on 512 → 64 → 512 check used `(1100.5,130,0.5)`, pitch 25, at yaw 0 and 90. Each radius phase settled for 400 ticks before the first full-resolution shot, then a camera-only `look` moved to yaw 90 and settled for 60 ticks before the second shot. `dhstatus` confirmed `512/null/512`, `64/64/512`, and `512/null/512` with `endPackActive=true`. In both views, the visible End island and smaller foreground silhouettes remained consistent. Mean RGB absolute difference for the yaw-0 lower `(0,480)-(1920,1080)` crop was 1.08/255 for A1–B and 1.11 for A1–A2; for yaw-90 `(0,630)-(1920,1080)`, 2.49 versus 1.65. Nebula animation varies above those crops. Full-resolution [yaw-0 A1](../harness/out/dh-end-outer-visual-20260924/a1-yaw0-512.png), [B](../harness/out/dh-end-outer-visual-20260924/b-yaw0-64.png), [A2](../harness/out/dh-end-outer-visual-20260924/a2-yaw0-512.png) and [yaw-90 A1](../harness/out/dh-end-outer-visual-20260924/a1-yaw90-512.png), [B](../harness/out/dh-end-outer-visual-20260924/b-yaw90-64.png), [A2](../harness/out/dh-end-outer-visual-20260924/a2-yaw90-512.png) are retained under ignored harness output. The watchdog armed/canceled with empty stderr.

**Status: 64 is promising with Art on, but not promoted.** The guard removes the demonstrated shader-off horizon problem in settled live checks, and central plus outer-island stills show no material silhouette loss. Before normal use, inspect continuous camera movement/flight for popping and measure display-on whole-frame A/B/A. All runs ended with shaders and both radius controls off, API override null, saved radius 512, the player back at the Nether portal in creative mode, and normal Minecraft exit. Original BenchCam jar, Iris properties, and options were restored byte-for-byte, and monitors were sent off. See [the BenchCam command and safety notes](../harness/benchcam/DH_NETHER_RADIUS_TRIAL.md).
