# BenchCam Iris GPU pass profiler prototype

This client-only BenchCam build times Iris 1.11.4+mc26.2 passes with OpenGL `GL_TIME_ELAPSED` queries. It does not change shader files, framebuffers, or the rendered image. It measures each Iris `begin`, `prepare`, `deferred`, and `composite` pass (compute, mipmap setup, and draw together), plus `final` when present. The shadow extension splits the former `shadow,draw_mips` interval into sequential `terrain_opaque_callbacks`, `entity_setup_extract`, `entity_submit`, `block_entity_extract`, `block_entity_submit`, `feature_render`, `buffer_end_frame`, `depth_copy`, `translucent_setup`, `terrain_translucent`, `post_translucent`, `mipmaps`, and `restore_state` rows, followed by `shadowcomp`. It does not time other geometry, Distant Horizons separately, shadow buffer clears, post-Iris UI, or presentation.

The composite hook is pinned to the installed Iris jar's `CompositeRenderer.renderAll` debug groups: one outer group, then one group per pass, including a separate pop for compute-only passes. `FinalPassRenderer.renderFinalPass` has a group around its shader-based final pass. The shadow hook begins at `GlStateManager._disableCull()` in `ShadowRenderer.renderShadows`, after Iris shadow frustum and terrain CPU setup. It switches at the first in-method `_viewport` call (after opaque terrain and optional callbacks), around the `renderEntities`, `renderBlockEntities`, `FeatureRenderDispatcher.renderAllFeatures`, `RenderBuffers.endFrame`, and `copyPreTranslucentDepth` calls, around the second `ChunkSectionsToRender.renderGroup` call (translucent terrain), around `generateMipmaps()`, and before `GLDebug.pushGroup(901, "shadowcomp")`. Entity and block-entity submit calls populate render nodes; `feature_render` and `buffer_end_frame` issue the later drawing work. `post_translucent` and `restore_state` expose intervening Iris CPU/GL work. The `shadowcomp` timer spans `ShadowCompositeRenderer.renderAll()` through the matching `GLDebug.popGroup()`. These boundaries were checked against the installed `iris-fabric-1.11.4+mc26.2.jar` bytecode. They are sequential and do not nest with the existing composite/final queries. Any Iris upgrade requires another bytecode check before using the numbers.

## Build and runtime gate

Build from the main repository:

```powershell
cd C:\Users\Trevor\codeprojects\mc-shader-bench\harness\benchcam
.\gradlew.bat build
```

The build reads the installed Iris jar from the ShaderBench Prism instance for compilation. Set `BENCHCAM_IRIS_JAR` to its path if it has moved. The output is `build\libs\benchcam-0.1.0.jar`. This optional build is **not installed in Prism by default**. The lead controls installation, the live game, shader selection, and monitors. A guarded RD12 Overworld smoke of the combined shadow timer captured 4,290 complete rows across 390 frames; see `harness/out/shadow-profile-smoke-20260924/findings.md`. The phase split subsequently ran guarded Art/candidate/Art captures at the same Overworld pose with 16 rows per frame, no drops, errors, or obvious rendering change; see `harness/out/vl-weather-ab-20260924/findings.md`. Profiler overhead and whole-frame gains remain unmeasured.

## Capture protocol

Use the existing BenchCam socket, for example from `harness`:

```powershell
py bench.py raw "gpuprof start gpu-pass-001.csv"
py bench.py raw "gpuprof status"
py bench.py raw "gpuprof stop"
py bench.py raw "gpuprof status"
```

`start` accepts a CSV basename only and creates a **new** file under `%USERPROFILE%\BenchCamGpuProfiles`. Directory components and UNC paths are rejected, and the output root is checked for link/junction redirection. It is off by default. `stop` stops issuing queries immediately but reports `draining` until old GPU results have arrived and the writer has closed. Continue rendering and poll `status` until `state=closed`, `pending=0`, `written=received`, `failed_reason=none`, `restart_required=false`, `writer_error=none`, and both dropped counters are zero. Keep the CSV with the exact pack revision, scene/camera, render/DH distance, resolution, and the paired control/candidate run order. Drop warmup frames in analysis. Never interpret pass sums as whole-frame GPU Busy or FPS.

`frame,stage,pass,gpu_ns,cpu_wall_ns` is the CSV schema. `frame` is BenchCam's render-frame ordinal within the client session. `cpu_wall_ns` is render-thread wall time from just after `glBeginQuery` through the post-`glEndQuery` error check. It includes the pre-end query ownership/error checks, driver calls, and timer overhead; it is not CPU Busy. Composite pass names come from Iris; the shadow phase labels are BenchCam's interval names. Results are polled at least four frames later, and `GL_QUERY_RESULT` is read only after `GL_QUERY_RESULT_AVAILABLE` is true. Query objects are reused with a 512-object ceiling and deleted after the capture drains. BenchCam checks `GL_CURRENT_QUERY` before beginning and before ending or aborting a timer, so it never ends another mod's elapsed query. If a capture fails, ended pending queries are deleted without waiting for results, and the file is closed. If deletion cannot be confirmed, `restart_required=true` rejects another capture until the client and GL context restart; `unreleased_queries` reports how many query IDs were left for context destruction. If the GPU falls behind, `dropped_queries` rises rather than blocking rendering. A separate bounded writer queue keeps file I/O off the render thread; `dropped_rows` and `writer_error` expose output loss. A method wrapper closes an active query and marks `failed_reason` when Iris exits a pass abnormally; a pass token prevents a later pass from ending another pass's query. GL errors from query creation, begin/end, polling, retrieval, and deletion are reported in `failed_reason`. Treat any failure reason, dropped query or row, incomplete drain, mixin injection failure, or GL error as a failed capture.

Each timer measures elapsed time between GPU query markers for submitted commands, including their dependencies, not isolated shader ALU time or GPU Busy. The intervals can include GPU idle time while the CPU prepares more draws. Comparing `cpu_wall_ns` with `gpu_ns` in the extraction/submission phases helps locate long render-thread work, but the difference cannot prove GPU idle or GPU Busy because previously queued GPU work may overlap the CPU interval. The shadow buffer clear happens earlier in `IrisRenderingPipeline.beginLevelRendering()` and is excluded. This pack declares no shadow texture mipmap options, whose Iris default is false, so `mipmaps` should contain only Iris's empty-loop state work; verify that empirically. A skipped translucent draw yields no `terrain_translucent` or `post_translucent` row. Compare matching phase rows in paired control/candidate captures at the same scene and camera. Do not sum them as a whole-frame estimate. More query boundaries may add overhead, so check profiler-off versus profiler-on frame time.

No broad terrain or DH timer is included. Iris wraps the normal `ChunkSectionsToRender.renderGroup()` call, Sodium injects a cancellable replacement into that method, and shadow rendering invokes the same method. A timer at the shared boundary would need reliable phase gating and live validation before its labels could be trusted. DH 3.3.2 also has before/after render events, but the Iris integration shown in `LodRendererEvents` mainly binds before events, and DH's `LodRenderer.render`/`renderDeferred` can occur in different frame phases. A broad DH span could overlap an Iris timer. The profiler conservatively fails captures if another elapsed query is active instead of nesting or ending a foreign query.

Guarded Overworld runtime captures confirmed the previous six shadow phases plus shadowcomp while the monitors were off and no obvious profiler rendering change. `mipmaps` measured about 0.001 ms in that scene. The finer entity/depth split and CPU wall column have passed an offline build but have not yet passed a live injection or overhead check. A translucent-skipped path, shadows-disabled path, and profile-off versus profile-on overhead were not measured; interpret the phase intervals accordingly.
